# 作業ログの作成・更新手順

作業ログは、作業テーマごとのディレクトリにある `work_log.md` へ記録する。
新しい作業テーマを開始するときは、必ず [work_log_template.md](work_log_template.md) を複製して使用する。

## 新しい作業テーマを開始する場合

1. 作業テーマに対応する番号付きサブディレクトリを `docs/work_log/` 以下に作成する。
2. [work_log_template.md](work_log_template.md) を `work_log.md` として配置する。
3. `# 作業テーマ名`、`## 目的`、`## 対象`を実際の内容へ書き換える。
4. 作業日を `YYYY-MM-DD` 形式で記載する。
5. `## 作業記録` の日付見出しへ作業内容を追記する。

## 既存の作業テーマへ追記する場合

1. 対象テーマの `work_log.md` を開く。
2. `## 作業記録` の末尾に作業日見出しを追加する。
3. `実施内容`、`確認結果`、`判断・注意事項`を記録する。
4. 同じ日に複数回作業した場合は、原則として同じ日付見出しへまとめる。
5. 作業により未完了事項が変わった場合は、`## 未完了事項`も更新する。

## 記録内容のルール

- 作業日を必ずログ本文に記載する。
- 実施した変更と、確認した結果を分けて記載する。
- テストを実行していない場合も、その理由を明記する。
- 外部APIや外部サービスを使用した場合は、接続結果と最終状態の確認結果を記載する。
- 判断理由、制約、未解決事項は作業ログに記録する。
- 完成後の機能仕様は作業ログではなく、`docs/specifications/`へ記載する。
- 仕様書に実装方針、作業手順、検討経緯を追加しない。

## 作業終了時の確認

- [ ] `work_log.md`を作業テーマの正しいディレクトリへ保存した。
- [ ] 作業日を記録した。
- [ ] 実施内容を記録した。
- [ ] テストや動作確認の結果を記録した。
- [ ] 未完了事項を更新した。
- [ ] 仕様変更がある場合、仕様書へ反映した。
