# プロジェクト運用・文書整理

## 2026-08-26

- 仕様書には機能仕様だけを記載し、実装方針・作業手順・検討経緯は作業ログへ記録する方針を定めた。
- 機能実装では、仕様を表すテストを先に作成し、未実装状態での失敗を確認してから実装する方針を定めた。
- 外部APIへの書き込みテストでは、書き込み後にデータを再取得して最終状態を検証する方針を定めた。
- 指示範囲外の仕様変更や動作変更を行わず、判断が必要な場合は事前に確認する方針を定めた。

## 2026-10-01

- 作業ログを日付単位のファイルから、作業テーマ単位の番号付きサブディレクトリへ整理する方針を決定した。
- 作業ログのファイル名はすべて `work_log.md` とし、作業日はログ本文に記録することにした。
- 仕様書は `specifications/` に残し、Architecture Decision Record用のディレクトリは作成しない方針とした。
- 作業ログの共通テンプレートを `docs/work_log_template.md` に作成した。
- 作業ログの作成・更新手順を `docs/work_log_procedure.md` に作成し、テンプレートを参照するようにした。
- テンプレートの日付見出しを固定日付から `YYYY-MM-DD` のプレースホルダーへ修正した。
