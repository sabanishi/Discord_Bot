# Scrapbox活動支援Discord Bot 現行仕様

## 1. 文書の目的

この文書は、現在のリポジトリに実装されているアプリケーションの共通仕様を記録する。
各機能の詳細は、以下の文書に分けて記載する。

- [日記ページ作成機能](日記ページ作成機能仕様.md)
- [日記更新確認機能](日記更新確認機能仕様.md)
- [被リンク数監視機能](被リンク数監視機能仕様.md)
- [戦術対抗戦ページ自動リファクタ機能](戦術対抗戦ページ自動リファクタ機能仕様.md)

## 2. アプリケーション概要

Scrapbox（Cosense）プロジェクトでの日記執筆とページ整理を支援するDiscord Botである。
BotはDiscordへログインして常駐し、次の処理を非同期の定期タスクとして実行する。

1. 毎日の日記ページ作成とDiscordへの案内
2. 日記ページが未更新の場合のDiscord通知
3. Scrapbox内で被リンク数が多くなったページの監視とDiscord通知
4. 戦術対抗戦ページの自動リファクタ
5. Scrapbox UserScriptからの戦術対抗戦ページ手動リファクタ

また、Renderなどの常駐Webサービス環境で稼働させるため、ヘルスチェック用のHTTPエンドポイント、戦術対抗戦ページを手動実行するHTTP API、通信中継UserScriptの配信エンドポイントを公開する。

## 3. 実行環境と依存関係

- Python 3.11（Dockerfileで指定）
- discord.py
- aiohttp
- Flask
- Werkzeug 3未満

コンテナ起動時は`python main.py`を実行する。

## 4. 起動時の動作

`main.py`を起動すると、以下の順で動作する。

1. 環境変数を読み込む。
2. 一部の設定値を検証する。
3. Flaskサーバーを別スレッドで起動する。
4. Discord Botを起動する。
5. Discordへのログイン完了後、各定期タスクを一度だけ開始する。

Discordの再接続などにより`on_ready`が複数回呼ばれても、定期タスクは重複起動しない。

## 5. 環境変数

アプリケーションで使用する環境変数を以下にまとめる。

| 変数名 | 必須 | デフォルト | 用途 |
| --- | --- | --- | --- |
| `DISCORD_TOKEN` | 必須 | なし | Discord Botのログイントークン |
| `DISCORD_DEFAULT_CHANNEL_ID` | 必須 | なし | 日記ページ作成通知の送信先チャンネルID |
| `DISCORD_ALERT_CHANNEL_ID` | 必須 | なし | 催促および異常通知の送信先チャンネルID |
| `COSENSE_PROJECT` | 必須 | なし | 操作対象のScrapboxプロジェクト名 |
| `COSENSE_SID` | 必須 | なし | Scrapbox認証に使う`connect.sid`の値 |
| `GYAZO_ACCESS_TOKEN` | 戦術対抗戦機能で必須 | なし | 生徒アイコン画像をGyazoへアップロードするためのアクセストークン |
| `CREATE_PAGE_TIME` | 任意 | `7:00` | 日記ページを作成する時刻 |
| `CHECK_PAGE_TIME` | 任意 | `21:15` | 日記ページの更新確認と戦術対抗戦ページの自動リファクタを実行する時刻 |
| `LINK_WARNING_ENABLED` | 任意 | `true` | 被リンク数監視の有効・無効 |
| `LINK_WARNING_INTERVAL_MINUTES` | 任意 | `30` | 被リンク数監視の実行間隔（分） |
| `LINK_WARNING_THRESHOLD` | 任意 | `30` | 警告を出す被リンク数 |
| `LINK_WARNING_RESOLVE_THRESHOLD` | 任意 | `25` | 警告済み状態を解除する被リンク数 |
| `LINK_WARNING_CONFIG_PAGE` | 任意 | 空文字 | 警告対象外ページを列挙する設定ページ名 |

## 6. Scrapbox通信の共通仕様

Scrapboxへの読み書きには`aiohttp`を使用する。認証には`COSENSE_SID`を`connect.sid` Cookieとして送信する。

ページ作成時はページデータimport用エンドポイントへmultipartリクエストを送り、`Origin`とプロジェクト設定画面の`Referer`を付与する。

ページURLを生成する際は、プロジェクト名とページタイトルをURLエンコードする。

## 7. Discord送信の共通仕様

送信先チャンネルは、DiscordクライアントのキャッシュからチャンネルIDで取得する。チャンネルが見つからない場合は送信せず、標準出力へ記録する。

メッセージが1800文字を超える場合は1800文字で切り、末尾へ省略メッセージを付ける。

Discord APIのエラーおよびその他の例外は捕捉し、標準出力へ記録する。Discordへの送信失敗によって定期実行ループ全体を停止させない。

## 8. 定期処理のエラー通知

以下の処理で例外が発生した場合、標準出力へエラーを記録したうえで、可能であれば警告チャンネルへ通知する。

- 日記ページ作成
- 日記ページ取得と更新確認
- 被リンク数の取得と判定
- 戦術対抗戦ページの取得とリファクタ

各定期処理は例外発生後もループを継続し、次回の実行を試みる。

## 9. UserScript手動実行API

`POST /api/tactical-challenge/refactor`で、指定した対象ページを1ページだけリファクタする。

- リクエストボディは`{"title": "ページ名"}`とする。
- 対象一覧に登録されていないページはHTTP 400で拒否する。
- 正常時はページ名、変更行数、新規アイコン数をJSONで返す。
- 入力不正はHTTP 400、サーバー処理失敗はHTTP 500でエラー内容をJSONで返す。
- UserScriptからのクロスオリジン通信を許可する。

`GET /userscripts/tactical-challenge-bridge.user.js`で、TampermonkeyおよびUserscriptsへ登録する通信中継UserScriptを配信する。
